# 融合方案讨论记录（2026-08-29，已与需求方确认）

## 一、功能冲突梳理与解决方案

### 冲突1【高风险】上传协议不匹配 —— 按需求文档方向解决
- **现状**：new_http/scriptD.js 上传的是 EPD 半字节打包数据（每像素4bit，192000字节），且 URL 依赖 DEVICE ID 输入框拼 `http://{ip}/dataUP`。
- **服务器要求**：svc_bmp.c 只接受 24 位 BMP（`bType=0x4D42 && biBitCount==24`），支持 800x480 或 480x800；http_server.c 原样收 body 不解析打包数据。
- **结论**：前端改为生成 800x480、24 位、RGB888 的 BMP（54 字节头 + 1152000 像素 = 1152054 字节），POST 相对路径 `/dataUP`。删除 DEVICE ID 输入框。通讯流程对齐 http 版（相对路径、进度提示、loading、超时处理）。

### 冲突2【中风险】转换算法输出色值必须是精确 EPD 六色
- **现状**：svc_bmp.c 的 `rgb_to_epd_color()` 是精确匹配（`==0/255/...`），不匹配的颜色一律归为白色。
- **结论**：前端转换算法（阈值/误差扩散）输出像素必须精确落回 COLOR6 六色（黑/白/黄/红/蓝/绿），禁止输出中间色，否则服务端大量误判为白色。分工：**前端负责裁图+转换到六色+生成24位BMP，服务端只负责 BMP→EPD 半字节打包**。

### 冲突3【中风险】图片溢出、边界不清
- **现状**：new_http 的 `<img>/<canvas>` 无 max-width 约束，超出蓝色背景框。
- **结论**：复用 http 的 `max-width:100%; max-height:100%; object-fit:contain` 方案，图片完整填充到蓝色边框内部，白色图片也有清晰边界。

### 冲突4【低风险】冗余功能删除
- 删除 DEVICE ID 输入框及其依赖；删除黑白（mono）两个转换按钮；删除 4bit 打包上传逻辑。

## 二、需求模糊点补充定义（已确认）

### 阈值偏移 = 黑白平衡权重
- 算法：最近色匹配（getNear）时，对黑/白两个颜色的距离误差乘系数 `monoScale = 1 - monoBalance/100*0.5`（范围 0.5~1.5）。
- 阈值偏移 > 0 → monoScale < 1 → 灰调像素更易归为黑/白（结果更干净）；< 0 → 更易归为彩色。与亮度/对比度效果不重叠。
- 滑块范围 -100~+100，默认 0。仅阈值算法显示。

### 裁剪偏移边框 —— 做

- 偏移值变化时实时重绘。功能目标：直观展示裁剪范围。

## 三、滑块与算法隔离规则
